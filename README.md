# MockMaker

A browser-based tool for making screen mockups from the official [NSW Government Design System](https://designsystem.nsw.gov.au). Drag real NSW components onto device frames, edit their text and options, then save and share the screens.

**Live site:** https://lanyard81.github.io/MockUps/ (available once GitHub Pages is switched on; see [Deploying](#deploying)).

> Status: Milestones 0–8 and the style-kit milestones S1–S6 (SharePoint kit) are done (scaffolding, canvas and device frames, component library, drag and drop, editing, layers and polish, saving and export, templates and samples, click-through prototypes). See [`docs/MILESTONES.md`](docs/MILESTONES.md).

## Run it locally

You need Node.js 22 or later.

```bash
npm install
npm run dev        # http://localhost:5173/MockUps/
```

Other scripts:

| Script                 | What it does                                               |
| ---------------------- | ---------------------------------------------------------- |
| `npm run lint`         | ESLint                                                     |
| `npm run format`       | Prettier (write). `format:check` only checks               |
| `npm run typecheck`    | TypeScript in strict mode                                  |
| `npm test`             | Vitest unit tests                                          |
| `npm run test:e2e`     | Playwright end-to-end tests (builds the site first)        |
| `npm run build`        | GitHub Pages build into `dist/`                            |
| `npm run build:single` | Single self-contained file at `dist-single/mockmaker.html` |

Playwright needs a Chromium. Run `npx playwright install chromium`, or point `PW_CHROMIUM` at an existing binary.

## Templates and samples

The Templates tab holds 22 official page templates (homepage, content, search, maps, theming, landing pages). Click one to add it as a new frame, or drag it onto a frame to replace that frame's content (you're asked first). Right-click a frame and choose Save as template to keep your own. The File menu opens three sample mockups.

## Click-through prototypes

Select a button or link and choose a frame under Go to frame. In Preview, clicking it opens that frame, with Back and Close. Exported HTML pages link to each other the same way.

## Style kits: NSW and SharePoint

Each frame is built with one style kit. **NSW** uses the real NSW Design System. **SharePoint** is a lookalike of a modern SharePoint Online page (built on Fluent UI design tokens, with no Microsoft logos or fonts), so you can mock up intranet pages too. Choose the kit when you add a frame; the library, templates and Properties follow the selected frame, and the two kits never mix inside a frame.

For SharePoint frames you get a theme (ready-made, Organisation or custom), site settings (site type, header, navigation, footer, page title area), sections (one to three columns, one-third left or right, full width, vertical, flexible, collapsible), 40 web parts, seven page templates, and **Copy as SharePoint build notes**: a plain-English spec a site owner can follow to build the page. **Convert to SharePoint** and **Convert to NSW** make a converted copy of a frame; anything with no equivalent becomes a labelled placeholder and is listed in a summary. See `docs/SHAREPOINT-OOB.md` for what is and isn't modelled.

## Freeform frames for sketching

For loose ideas, make a frame **Freeform** (Properties → Layout, or Freeform in the Add frame menu). Components land exactly where you drop them and move anywhere, with no grid or snapping: drag to move (Shift locks a direction), drag the side handles to resize, arrow keys nudge, and Alt+↑/↓ changes what is in front. Switch a frame back to **Flow** to tidy it into sections.

## Tracing over a screenshot

Select a frame and paste a screenshot (or drop one on the frame, or use **Reference image** in Properties). It is drawn faintly over the frame so you can rebuild the page on top; choose Over, Behind or Beside, change the opacity and size, and hide it with Ctrl/⌘ Shift R. It only shows while editing: never in Preview, PNG or HTML export, or templates.

## Working from screenshots with Claude

Copy the instructions (**File → Copy page spec instructions**), paste them into a Claude chat with a screenshot, and paste the JSON answer back into the editor (or **File → Import page spec…**, or drop the `.page.json` file). It becomes a new frame, and anything Claude couldn't match is a labelled placeholder. **Copy as page spec** on any frame goes the other way, so a frame can be changed in a chat and brought back. The format and every component are in [`docs/PAGE-SPEC.md`](docs/PAGE-SPEC.md), generated by `npm run page-spec-docs`.

## Saving and sharing

- **Autosave:** work is saved in your browser as you go ("Saved" beside the mockup name). **File → My mockups…** lists everything you've made.
- **Files:** **File → Save to file** makes a `.mockup.json` with images inside, which you can open on any computer with **Open file** (or by dropping it on the editor).
- **Export:** **File → Export…** makes PNGs (1× or 2×, full height) or clickable HTML pages built with the real NSW Design System, either self-contained (works offline) or linking to NSW. **Copy HTML of selection** gives developers clean markup.

If your browser won't keep data for the page (private windows, some `file://` setups) a banner says so; use **Save to file** to keep your work.

## The single-file version

`npm run build:single` produces `dist-single/mockmaker.html`. The app, NSW CSS and JavaScript, fonts and icons are all inlined, so you can open it straight from disk with no internet connection. Every push to `main` uploads it as a build artifact in GitHub Actions, and pushing a version tag (for example `v0.1.0`) attaches it to a GitHub Release.

## Deploying

CI (`.github/workflows/ci.yml`) runs lint, formatting, type-check, unit tests and end-to-end tests, then deploys to GitHub Pages from `main`.

One-off setup: in the repository go to **Settings → Pages** and set **Source** to **GitHub Actions**.

Vite's `base` is `/MockUps/` (the repository name). If you rename the repository, update the default in `vite.config.ts` and `playwright.config.ts`. The deploy job sets it automatically from the repository name.

## Updating the NSW Design System

```bash
npm install nsw-design-system@latest
npm run catalogue     # re-checks every snippet against the new CSS and JS, and regenerates the catalogue
npm test && npm run test:e2e
```

`npm run catalogue` fails and lists any class that no longer exists in the new version. Fix those snippets in `src/kits/nsw/catalogue/sources/`, run it again, and commit `src/kits/nsw/catalogue/generated/catalogue.json`. Frames load the CSS and JavaScript from the installed package, so upgrading the package upgrades every mockup. Check `docs/NSW-DESIGN-SYSTEM.md` for components that need attention after an upgrade.
